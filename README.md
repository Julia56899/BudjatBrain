BudjatBrain -  это полноценный финансовый трекер с автоматической категоризацией расходов и персонализированных рекомендаций по оптимизации бюджета.
  Базовый функционал приложения: 
  1.Автоматическая категоризакция доходов и расходов, если пользователь не указал дто категорию, а написал в описании что это 
2.персональные рекомендации в конце каждого месяца в отношении качественной оптимизации расходов и доходов
3. Расчёт баланса в реальном времени
4.Анализ расходов по категориям
5.Месячная статистика

Интеллектуальные функции
- Автоматическая категоризация— с помощью хеш мап – ключевых слов возможно определение базовых категорий по словам в описании из категориДТО (то, что заполнил юзер при добавлении транзакции)
- Умные рекомендации — 6 практических советов по оптимизации финансов:
1. Крупная единичная трата:
Срабатывает, когда отдельная покупка > 50% вашего месячного дохода
Пример: доход 100к руб. → порог 50к руб.
2. Перерасход на питание:
Срабатывает, когда траты на "Еду" > 40% от всех ваших расходов за месяц
Пример: общие расходы 70к руб. → порог на еду 28к руб.
3. Отсутствие накоплений:
Срабатывает, когда нет ни одной транзакции в категории "Накопления" за текущий месяц
4. Импульсивные расходы на развлечения:
Срабатывает, когда сумма трат на "Развлечения" в один день > 30% вашего среднедневного дохода
Пример: месячный доход 90к руб., в месяце 30 дней → среднедневной доход 3к руб. → порог 900 руб.
5.Критический дисбаланс бюджета:
Срабатывает, когда общие расходы > 90% вашего месячного дохода
Пример: доход 100к руб., расходы 91к руб. → рекомендация
6.Пропущенные обязательные платежи:
Срабатывает, когда нет трат в категориях "Жильё" или "Здоровье" за 2 месяца подряд
Проверяет ключевые жизненные расходы
Все пороги четкие, измеримые и основаны на финансовой логике. Каждая рекомендация имеет конкретное математическое условие срабатывания.

•	Поиск по ключевым словам — система определяет категорию по словам в описании (например, "макдак" → "Еда")
Сборка проекта:
•	Maven — инструмент для сборки проекта и управления библиотеками
Тестирование
•	Postman — программа для проверки работы API-запросов

Как работает категоризация в  проекте BudjetBrain
Основной принцип:
Система использует словарный поиск (keyword matching) для определения категории по описанию транзакции.
Как это работает:
Подготовка словаря - при запуске приложения создается HashMap с парами "ключевое слово" → "категория"
Поиск совпадений - описание транзакции разбивается на слова и сравнивается с ключами в словаре
Первое совпадение - система возвращает категорию первого найденного ключевого слова
 Технические детали:
1. Словарь (map) содержит:
map.put("мак", "Еда");        // ключ → значение
map.put("такси", "Транспорт"); // слово → категория
2. Поиск происходит так:
 Вход: "Купил продукты в пятерочке"
 1. Приводим к нижнему регистру:
description = "купил продукты в пятерочке"
2. Ищем последовательно:
Есть ли "мак" в строке? → НЕТ
 Есть ли "продукты" в строке? → ДА 
/map.get("продукты") → "Еда"
3. Возвращаем: "Еда"
3. Если совпадений нет:
 Вход: "оплата за обэд" (с опечаткой)
Ищем: "обэд" нет в словаре
→ Возвращаем "прочее"
Примеры работы:
Описание транзакции	Найденное слово	Категория
"Обед в макдаке"	"макдак"	Еда
"Поездка на такси"	"такси"	Транспорт
"Оплата интернета"	"интернет"	Жильё
"Билеты в кино"	"кино"	Развлечения
"Купил обэд"	(не найдено)	Прочее
"Оплата за обеД"	"обед" → нет в словаре	Прочее
 Важные особенности:
Чувствительность к регистру - все слова приводятся к нижнему регистру
Точное совпадение - нужны точные ключевые слова из словаря
Опечатки не обрабатываются - "обэд" ≠ "обед", "магдак" ≠ "макдак"
Первое совпадение - если несколько ключей найдены, берется первый.
Для точной работы:
Правильно:
"Обед в макдональдсе" → найдется "мак" → "Еда"
 "Заправка бензина" → найдется "заправка" → "Транспорт"
Неправильно:
 "Обед в магдаке" → не найдется (опечатка) → "Прочее"
 "Купил мясо и хлеб" → не найдется (нет ключевых слов) → "Прочее"
Как улучшить точность:
Добавлять больше синонимов в словарь.
Использовать популярные названия ("пятерочка", "магнит").

Важные замечания:
1. Порядок важен: Сначала создайте пользователя, потом категории, потом транзакции
2. ID категории: При создании транзакции используйте `categoryId` из ответа создания категории
